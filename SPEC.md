# AlexTerminal — техническое задание

Версия: 0.1 (черновик), 18 октября 2026.

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Название | AlexTerminal |
| Тип | Настольный эмулятор терминала с GPU-рендерингом |
| Язык | Rust (stable, edition 2024) |
| Платформы | macOS 13+ (Apple Silicon и Intel), Linux (X11 и Wayland; glibc ≥ 2.31) |
| Лицензия | На усмотрение владельца (рекомендуется MIT или Apache-2.0) |
| Исполняемый файл | `alexterminal` (CLI-псевдоним `alt`) |

Ключевая идея: полноценный терминал уровня Alacritty/WezTerm по эмуляции, но с собственной моделью рабочего пространства:

1. Вкладки — вертикальный список слева, с древовидной вложенностью.
2. В каждой вкладке до 4 панелей терминала: вертикальный стек или сетка 2×2.
3. У каждой панели своя история команд в файле.
4. Полное восстановление состояния приложения после закрытия (слепок).
5. Индикация на вкладке: активное удалённое соединение, выполняющаяся команда.
6. Горячие клавиши для всего, что есть в интерфейсе.
7. Открыть текущую папку панели в Finder (macOS) или файловом менеджере (Linux).
8. Сессии живут, пока запущено приложение: выход и закрытие последнего окна завершают shell-процессы. Структура, папки и последние строки вывода восстанавливаются из слепка при следующем запуске. (Решение от 22.10.2026, см. §14.)
9. Несколько окон и профили вкладок.
10. Интерфейс на русском и английском, язык — системный.

## 2. Термины

| Термин | Определение |
|---|---|
| Окно | Окно ОС со своим сайдбаром и набором вкладок. Окон может быть несколько; вкладки переносятся между окнами. |
| Сервер сессий | Поток внутри процесса `alexterminal` (крейт `at-daemon`), который владеет PTY и shell-процессами всех панелей, деревом окон и слепком. Окна общаются с ним сообщениями `at-proto`. Завершается вместе с приложением. |
| Сайдбар | Левая колонка со списком вкладок. |
| Профиль | Именованный набор параметров для создания вкладки: shell, cwd, стартовая команда, окружение, цвет. |
| Вкладка (tab) | Узел дерева в сайдбаре. Содержит 1–4 панели и может содержать дочерние вкладки. |
| Панель (pane) | Один эмулятор терминала с собственным PTY, shell-процессом, scrollback и историей команд. |
| Раскладка (layout) | Способ размещения панелей внутри вкладки: `Stack` (вертикальный стек) или `Grid` (2×2). |
| Слепок (snapshot) | Сериализованное состояние приложения, по которому оно восстанавливается при запуске. |
| Shell-интеграция | Скрипты для zsh/bash/fish, которые сообщают терминалу через OSC-последовательности текущую папку, начало и конец команды, удалённый хост. |

## 3. Архитектура и технологический стек

### 3.1 Выбор библиотек

| Слой | Решение | Обоснование |
|---|---|---|
| Эмуляция терминала (парсер VT, сетка, scrollback) | `alacritty_terminal` | Зрелый, быстрый, используется Alacritty и Zed. Не тянуть свой парсер. |
| PTY | `portable-pty` (или `tty`-модуль `alacritty_terminal`) | Кроссплатформенный fork/exec, resize, сигналы. |
| GUI | `iced` (бэкенд `wgpu`, текст через `cosmic-text`) | Elm-архитектура хорошо ложится на сложное состояние (дерево вкладок, слепки). `cosmic-text` даёт качественный шейпинг, лигатуры, fallback-шрифты. Есть референс `iced_term`. |
| Альтернатива GUI | `gpui` (фреймворк Zed) | Лучший рендер текста, но слабая документация и нестабильный API. Решение зафиксировать на этапе M0 после прототипа (см. §13). |
| Конфиг | `serde` + `toml` | Человекочитаемый файл настроек. |
| Слепок | `serde` + `serde_json` (атомарная запись через временный файл + `rename`) | Простая отладка, диффы. |
| Пути | `directories` | XDG на Linux, `~/Library/Application Support` на macOS. |
| Информация о процессах | macOS: `libproc` (`proc_pidinfo`, `PROC_PIDVNODEPATHINFO`); Linux: `/proc/<pid>/cwd`, `/proc/<pid>/comm` | Определение cwd и имени foreground-процесса панели без shell-интеграции. |
| Горячие клавиши | Собственный модуль `keymap` поверх событий `iced`/`winit` | Нужны платформенные модификаторы и перенастройка. |
| Протокол GUI ↔ демон | Unix-сокет, кадры `u32 длина + MessagePack` (`rmp-serde`); `tokio` в демоне | Простой, без зависимости от D-Bus/XPC; один код для обеих платформ. |
| Локализация | `fluent` + `fluent-templates`, бандлы `locales/ru/*.ftl`, `locales/en/*.ftl` | Склонения и множественное число в русском. |
| Логирование | `tracing` + `tracing-subscriber`, ротация файлов | |
| Ошибки | `anyhow` на уровне приложения, `thiserror` в модулях | |

### 3.3 Процесс: интерфейс и сервер сессий

```
┌──────────────────────── alexterminal (один процесс) ─────────────────────┐
┌────────────────┐    каналы        ┌─────────────────────────────┐
│ интерфейс      │◄───────────────►│ сервер сессий (поток)        │
│ (iced, окна)   │  at-proto        │  ├ Pane: PTY + alacritty     │
│                │                  │  │   grid + scrollback       │
│ рендер, ввод,  │                  │  ├ Pane …                    │
│ сайдбар,       │                  │  ├ дерево окон/вкладок       │
│ настройки      │                  │  ├ слепок + история (persist)│
└────────────────┘                  │  └ procinfo                  │
                                    └─────────────────────────────┘
```

**Сервер сессий** — единственный владелец состояния сессий, работает потоком внутри процесса приложения и завершается вместе с ним. Один экземпляр на пользователя (lock-файл `instance.lock`). Сервер также слушает `instance.sock`: через него второй запуск `alexterminal` передаёт запрос (новая вкладка или окно) уже открытому приложению, а `alexterminal list` читает состояние. Отдельного фонового процесса нет. До версии 0.3 сервер был отдельным процессом `alexterminal-server`, который переживал закрытие окон. Новая версия при запуске находит такой старый сервер, просит его сохранить слепок, останавливает и восстанавливает сессию из слепка.

В демоне на каждую панель — поток чтения PTY, который кормит парсер `alacritty_terminal`. Клиенту отправляются только изменившиеся области сетки (dirty rows) плюс события (заголовок, cwd, состояние, bell), с коалесцированием не чаще `max_fps`. Scrollback хранится в демоне; клиент запрашивает диапазон строк по мере прокрутки и кэширует.

**GUI** — тонкий клиент: рендер, ввод, сайдбар, окна, настройки. Клавиши и мышь уходят в демон как `Input{pane, bytes}` / `Resize{pane, cols, rows}`. Кроме окон приложения, к серверу через сокет ненадолго подключаются второй запуск `alexterminal` и `alexterminal list`.

Протокол (`at-proto`), основные сообщения:

| Направление | Сообщение |
|---|---|
| → демон | `Hello{proto_version}`, `CreateWindow`, `CreateTab{window, parent, profile, cwd}`, `CreatePane{tab}`, `ClosePane{pane, force}`, `MoveTab{tab, window, parent, index}`, `SetLayout`, `SetSizes`, `Input`, `Resize`, `ScrollbackRange{pane, from, to}`, `Search`, `GetHistory{pane}`, `Detach`, `Shutdown{kill_sessions}` |
| → клиент | `Welcome{state_snapshot}`, `TreeChanged{...}`, `GridDelta{pane, rows}`, `PaneState{pane, state, cwd, title, remote}`, `Bell{pane}`, `PaneExited{pane, code}`, `ScrollbackChunk`, `SearchResult`, `Error` |

Версия протокола проверяется при `Hello`. Старый отдельный сервер (до 0.3) новая версия останавливает с сохранением слепка и восстанавливает сессию из него (§3.3). Если на сокете отвечает более новая версия приложения, запуск завершается с ошибкой.

### 3.4 Ограничения

- Нет Electron/веб-рендера. Только нативный GPU-рендер.
- Нет сетевых запросов из приложения (кроме явных действий пользователя в shell).
- Сокет приложения доступен только владельцу (`0600`); удалённый доступ не предусмотрен.
- Если поток сервера завершился, приложение выходит; следующий запуск восстанавливает окна из слепка.

## 4. Функциональные требования

### 4.1 Окно и общая компоновка

```
┌──────────────────────────────────────────────────────────────┐
│ ○ ○ ○   AlexTerminal                                          │  заголовок ОС (macOS: прозрачный, с traffic lights)
├──────────────┬───────────────────────────────────────────────┤
│  САЙДБАР     │  ОБЛАСТЬ ПАНЕЛЕЙ                               │
│ ▸ work   ●   │  ┌─────────────────────────────────────────┐  │
│   ├ api  ◐   │  │ pane 1                                  │  │
│   └ db   ⇅   │  ├─────────────────────────────────────────┤  │
│ ▸ home       │  │ pane 2                                  │  │
│ ▸ srv-01 ⇅   │  └─────────────────────────────────────────┘  │
│              │                                               │
│  [+]  [⚙]    │                                               │
└──────────────┴───────────────────────────────────────────────┘
```

- Сайдбар: ширина по умолчанию 220 px, диапазон 160–400 px, перетаскивается, запоминается на окно. Можно скрыть (`Cmd+B`); при скрытом сайдбаре название активной вкладки показывается в заголовке окна.
- Нижняя кромка сайдбара: кнопки «новая вкладка» (клик — обычная, долгое нажатие или `▾` — выбор профиля) и «настройки».
- Статусная строка не нужна; всё, что нужно, показывается на вкладке и в заголовке панели.

**Несколько окон.**

- `Cmd+N` — новое окно с одной вкладкой. Каждое окно имеет свой сайдбар, набор вкладок, геометрию и состояние сайдбара; настройки и темы общие.
- Перенос вкладки: перетаскивание из сайдбара за пределы окна создаёт новое окно; перетаскивание в сайдбар другого окна переносит её туда (со всеми панелями и детьми). Из меню/палитры: «Переместить вкладку в окно…» и «Вкладку в новое окно» (`Cmd+Shift+N`).
- Закрытие окна (`Cmd+Alt+W` или красная кнопка), когда открыты другие окна, **не завершает** его вкладки: они остаются «отсоединёнными», пока приложение запущено, и доступны через палитру. Настройка `close_window = detach | close_tabs | ask` (по умолчанию `detach`).
- Закрытие последнего окна — это выход (§4.8): сессии завершаются, при следующем запуске окна восстанавливаются из слепка.
- `Window` меню перечисляет окна; `Cmd+\`` переключает между ними.

### 4.2 Вкладки (сайдбар)

**Модель.** Два уровня. Вкладка верхнего уровня — **группа**: у неё нет своего терминала, только список вложенных вкладок, заголовок, режим отображения и флаг свёрнутости. **Вложенная вкладка** — это окно терминала с 1–4 панелями. Вложить вкладку во вложенную вкладку нельзя. Пустая группа удаляется автоматически. Отступ вложенных вкладок — 14 px.

**Операции.**

| Операция | Поведение |
|---|---|
| Создать вкладку | Создаётся новая группа после текущей, в ней одна вложенная вкладка-терминал, она становится активной. Одна панель, cwd = cwd активной панели (настройка `new_tab_cwd`: `inherit` / `home` / путь). Используется профиль `default`. |
| Создать вкладку из профиля | `Cmd+Alt+T` открывает список профилей (поиск по имени, `Enter`); вкладка получает shell, cwd, команду, окружение и цветовую метку профиля. См. §4.13. |
| Создать вложенную вкладку | Новая вкладка-терминал в текущей группе, сразу после активной. cwd наследуется. Вкладку внутри вложенной вкладки создать нельзя. |
| Закрыть вкладку | Закрываются все её панели. Если это последняя вкладка группы, группа тоже удаляется. Закрытие группы закрывает все её вкладки. Если в панелях есть выполняющаяся команда или удалённое соединение — подтверждение (настройка). `Cmd+Shift+Z` возвращает вкладку на прежнее место в группе. |
| Переименовать | Двойной клик или `Cmd+Shift+E`. Пустое имя — вернуться к автозаголовку. |
| Автозаголовок | Приоритет: OSC 0/2 от программы → имя удалённого хоста → последний сегмент cwd. Для вкладки с несколькими панелями — заголовок активной панели. |
| Переставить | Drag-and-drop: сброс на середину строки объединяет вкладку с группой этой строки; сброс выше или ниже вложенной строки ставит вкладку в ту же группу на это место; выше или ниже строки верхнего уровня — отдельной группой. Группа перетаскивается целиком. Клавиатура: `Cmd+Shift+↑/↓` перемещает внутри группы (одиночную группу — среди групп), `Cmd+Shift+→` переносит вкладку в группу выше, `Cmd+Shift+←` выносит её в отдельную группу. |
| Режим отображения группы | Вкладки группы показываются либо по одной (по умолчанию), либо все вместе: секциями друг под другом в одном окне, в порядке списка. Каждая секция — заголовок вкладки и её 1–4 панели. Высоты секций меняются перетаскиванием границ и сохраняются в слепке (`group_view`, `group_sizes`). Переключение: `Cmd+Shift+G` (Linux `Ctrl+Shift+G`), контекстное меню, палитра. Доступно, если в группе две вкладки и больше. Клик в секцию делает её вкладку активной; у группы в сайдбаре значок ▤. Вместо стопки секции можно разложить плиткой — почти квадратной сеткой равных ячеек, неполный последний ряд растягивается на всю ширину (`group_tiles`; `Cmd+Alt+G`, Linux `Ctrl+Shift+Alt+G`, палитра; если режим группы выключен, он включается сразу плиткой). В контекстном меню группы раздел «Вид группы» с выбором: «По одной», «Одна под другой», «Плиткой» — текущий отмечен галочкой. В плитке размеры ячеек не перетаскиваются; значок группы ▦. |
| Свернуть/развернуть группу | Клик по шеврону или `Cmd+Shift+.`. Группа из одной вкладки по умолчанию показывается одной строкой этой вкладки, без шеврона, и развернуть её нельзя (настройка `expand_single_tab_groups`, по умолчанию `false`). Свёрнутая группа показывает агрегированный индикатор вкладок и подсвечивается, когда активна одна из них. |
| Переключение | Клик, `Cmd+1…9` (по видимому порядку), `Ctrl+Tab` / `Ctrl+Shift+Tab` (по порядку обхода дерева), `Cmd+Shift+[` / `]`. |
| Контекстное меню | Новая вкладка, новая вложенная, переименовать, дублировать, закрыть, закрыть остальные, открыть папку в Finder. |

**Отображение строки вкладки.**

```
[шеврон] [иконка состояния] Название            [счётчик панелей] [×]
```

- Если вкладка создана из профиля с цветом — слева тонкая (3 px) цветная метка профиля; у активной вкладки она заменяет акцентную полосу.
- Счётчик панелей показывается только если панелей > 1: `2/4`. Строка группы показывает число вкладок.
- Кнопка закрытия появляется при наведении.
- Активная вкладка: заливка `surface_active` и акцентная полоса 3 px слева.

### 4.3 Индикаторы состояния

Состояние панели вычисляется непрерывно. Состояние вкладки — максимум по приоритету среди её панелей (и детей, если ветка свёрнута).

| Приоритет | Состояние | Условие | Индикатор | Цвет |
|---|---|---|---|---|
| 1 | `Attention` | Звонок (BEL) или завершение команды дольше `attention_threshold` (5 с) в неактивной вкладке | Точка | `accent_warn` (янтарь) |
| 2 | `Remote` | Foreground-процесс из списка `remote_programs` (`ssh`, `mosh-client`, `telnet`, `et`, `kubectl exec`, `docker exec`, `nc`) или OSC `1337;RemoteHost` / собственный `OSC 7770;remote=host` от shell-интеграции | Иконка «две стрелки» ⇅ плюс tooltip с хостом | `accent_remote` (зелёный) |
| 3 | `Running` | Между OSC 133;C и 133;D, либо foreground pgid ≠ pgid shell больше 300 мс | Полукруг-спиннер (вращение 1 об/с; настройка `animate_indicators`) | `accent_info` (синий) |
| 4 | `Exited` | Shell-процесс завершился | Пустой круг | `fg_muted` |
| 5 | `Idle` | Промпт | Ничего | — |

`Remote` и `Running` могут совпадать (команда внутри ssh): показывается `Remote`, а спиннер — в заголовке панели.

Сброс `Attention` — при активации вкладки.

Каждая панель также имеет тонкую строку заголовка (высота 22 px, можно скрыть): `[индикатор] host:cwd  [pid процесса]  [⤢ развернуть] [×]`.

### 4.4 Панели внутри вкладки

- От 1 до 4 панелей. По умолчанию одна.
- Раскладки:
  - `Stack` — вертикальный стек (одна колонка, N строк). Доступна при 1–4 панелях.
  - `Grid` — сетка 2×2. Доступна только при 4 панелях; при закрытии панели из `Grid` раскладка автоматически становится `Stack`.
  - Переключение `Cmd+Shift+M` (работает только при 4 панелях; иначе ничего не делает и мигает кнопкой).
- Разделители перетаскиваются мышью; минимальный размер панели — 5 строк × 20 колонок. Пропорции сохраняются в слепке (`sizes: Vec<f32>` для стека, `rows: [f32;2], cols: [f32;2]` для сетки).
- «Развернуть панель» (`Cmd+Shift+Enter`): временно занимает всю область; повторное нажатие возвращает.
- Фокус: клик, `Cmd+Alt+↑/↓/←/→` по геометрии, `Cmd+Alt+1…4` по индексу.
- Новая панель (`Cmd+D`) добавляется после активной, cwd наследуется; при 4 панелях — действие недоступно.
- Закрыть панель (`Cmd+W`): если панель последняя — закрывается вкладка.
- Порядок панелей можно менять (`Cmd+Alt+Shift+↑/↓`).
- Равные размеры: `Cmd+Alt+=`.

### 4.5 Эмуляция терминала (минимум для «полноценного терминала»)

- VT100/VT220/xterm-совместимость уровня `alacritty_terminal`: `TERM=xterm-256color`, truecolor, 256 цветов, курсорные режимы, альтернативный экран, bracketed paste, mouse reporting (X10, SGR 1006), focus events, OSC 0/2 (заголовок), OSC 7 (cwd), OSC 8 (гиперссылки), OSC 52 (буфер обмена — по умолчанию только запись, настройка), OSC 133 (prompt marks), DEC private modes, Sixel — не требуется в 1.0.
- `terminfo`: поставлять `alexterminal` в пакете, но по умолчанию выставлять `TERM=xterm-256color` для совместимости с удалёнными хостами. `TERM_PROGRAM=AlexTerminal`, `TERM_PROGRAM_VERSION`.
- Unicode: широкие символы (CJK), emoji, комбинируемые знаки, ZWJ, корректная ширина по `unicode-width`.
- Scrollback: по умолчанию 10 000 строк на панель (настройка до 100 000). Прокрутка колесом, `Shift+PgUp/PgDn`, `Cmd+Home/End`. Индикатор «есть новое внизу» при прокрутке вверх.
- Выделение: мышь (символьное, слово по двойному клику, строка по тройному), `Alt+drag` — прямоугольное. Копирование `Cmd+C`, настройка `copy_on_select`. Вставка `Cmd+V`; многострочная вставка — предупреждение (настройка).
- Поиск по scrollback: `Cmd+F`, строка поиска внизу панели, регистронезависимый, regex-переключатель, `Enter`/`Shift+Enter` — следующий/предыдущий, подсветка всех совпадений.
- Ссылки: распознавание URL и путей; `Cmd+клик` открывает (URL — браузер, путь — Finder/редактор по настройке).
- Звонок: визуальный (вспышка рамки панели), звуковой, индикатор на вкладке — настройка.
- Курсор: блок/подчёркивание/черта, мигание (настройка), курсор неактивной панели — полый.
- Очистка экрана `Cmd+K` (сброс scrollback до текущего промпта).
- Изменение размера шрифта `Cmd+=`, `Cmd+-`, `Cmd+0` — на окно.
- Прозрачность и размытие фона (macOS: `NSVisualEffectView`; Linux: только альфа) — настройка, по умолчанию выключено.

### 4.6 Shell-интеграция

Цель — надёжно знать cwd, границы команд и удалённый хост без опроса процессов.

- Поддержка zsh, bash (≥ 4.4), fish. Скрипты в `assets/shell/`.
- Автоинъекция (настройка `shell_integration = auto | manual | off`):
  - zsh: `ZDOTDIR` на временный каталог с `.zshenv`, который загружает `at.zsh`, затем возвращает пользовательский `ZDOTDIR`.
  - bash: `--rcfile` с обёрткой, которая source-ит пользовательский `~/.bashrc` и `at.bash`.
  - fish: `XDG_DATA_DIRS` с `vendor_conf.d/at.fish`.
- Скрипты отправляют: `OSC 7` (cwd как `file://host/path`), `OSC 133;A/B/C/D;exit=N`, `OSC 7770;cmd=<base64 команды>` перед выполнением (для истории), `OSC 7770;remote=<host>` при ssh через функцию-обёртку `ssh` (включается настройкой; обёртка не меняет аргументы).
- Если интеграции нет (удалённый хост без скриптов, `sh`), работают эвристики из §4.3 и `procinfo`.

### 4.7 История команд на панель

- Каждая панель имеет стабильный `pane_id` (ULID), который переживает перезапуски.
- Файл: `<data_dir>/history/<pane_id>.hist`. Формат — строки `"<unix_ms>\t<cwd>\t<exit>\t<команда>"`, команда с экранированием `\n` → `\\n`. Запись через `OSC 7770;cmd` (сразу при старте) и дополнение кодом выхода при `OSC 133;D`.
- Параллельно панели выставляется `HISTFILE=<data_dir>/history/<pane_id>.zsh_history` (и аналог для bash/fish), чтобы стрелка вверх в shell тоже была пер-панельной (настройка `per_pane_shell_history`, по умолчанию `true`; `false` — HISTFILE не трогать).
- Просмотр: `Cmd+Shift+H` — всплывающий список истории текущей панели с поиском; `Enter` вставляет команду в строку ввода, `Cmd+Enter` выполняет.
- Ротация: не более `history_max_entries` (10 000) строк в `.hist`; при превышении удаляются старые.
- При закрытии вкладки файл истории не удаляется в течение `history_retention_days` (30), чтобы восстановление через «отменить закрытие» (`Cmd+Shift+T` в первые 10 минут) вернуло историю.

### 4.8 Сессии, detach, слепок и восстановление

Есть два уровня сохранности:

1. **Живые сессии** — пока приложение запущено. Закрытие окна, кроме последнего, по настройке `close_window` может оставить его вкладки отсоединёнными, их процессы продолжают работать.
2. **Слепок на диске.** При выходе и после перезагрузки по слепку пересоздаются окна, дерево, панели, cwd, последние строки scrollback; shell-процессы запускаются заново.

**Что сохраняется в слепке** (`<data_dir>/session.json`, версия схемы в поле `schema`); пишет его сервер сессий:

```json
{
  "schema": 2,
  "saved_at": "2026-10-18T10:00:00Z",
  "windows": [
    {
      "id": "01W...", "x": 100, "y": 80, "w": 1440, "h": 900, "maximized": false,
      "sidebar_width": 220, "sidebar_hidden": false, "active_tab": "01J...",
      "tabs": [
        {
          "id": "01J...", "custom_title": "work", "profile": "default", "collapsed": false,
          "layout": "stack", "sizes": [0.5, 0.5], "active_pane": "01K...",
          "panes": [
            { "id": "01K...", "cwd": "/Users/a/src/api", "title": "api", "font_scale": 1.0,
              "remote": { "host": "srv-01", "command": "ssh srv-01" },
              "last_state": "remote", "scrollback_file": "scrollback/01K....txt" }
          ],
          "children": [ ]
        }
      ]
    }
  ],
  "detached_tabs": [ ]
}
```

`detached_tabs` — вкладки окон, которые пользователь закрыл с режимом `detach`; они не привязаны к окну и доступны через `Window → Detached tabs…`.

- Scrollback панели сохраняется отдельно в `<data_dir>/scrollback/<pane_id>.txt` — последние `restore_scrollback_lines` (2 000) строк, с SGR-атрибутами, переизлучёнными как ANSI-последовательности. Настройка `restore_scrollback = true`.
- Запись атомарная. Хранятся `session.json` и `session.json.bak` (предыдущий успешный).

**Закрытие окна** — см. §4.1 (`close_window`, по умолчанию `detach`): вкладки остаются отсоединёнными, пока приложение запущено. Закрытие последнего окна — это выход.

**Выход (`Cmd+Q`, «Quit», закрытие последнего окна).**

1. Если есть панели в состоянии `Running` или `Remote` и включено `confirm_quit_when_busy` — диалог со списком: «Выполняется: 2, Соединений: 1. Выйти из AlexTerminal?».
2. Сервер сохраняет слепок, scrollback и геометрию окон (блокирующе, таймаут 3 с).
3. Для каждой панели: закрыть PTY (ведущая сторона), что даёт `SIGHUP` группе процессов — так ssh корректно завершает соединение. Ожидание выхода shell до 2 с, затем `SIGTERM`, через 1 с — `SIGKILL`.
4. Дописать в `.hist` незавершённые команды с `exit=-1`.
5. Приложение завершается.

**Выключение компьютера / logout.** Сессии закрываются вместе с приложением. Слепок остаётся от последнего автосохранения.

**Запуск GUI.**

0. Если приложение уже запущено (отвечает на `instance.sock`) — передать ему запрос и выйти. Конец.
1. Иначе запустить сервер сессий в своём процессе; тот, если `restore_session = true` и есть `session.json`, восстанавливает окна, дерево, панели, раскладки, размеры, заголовки.
2. Для каждой панели: cwd — если каталог не существует, использовать `$HOME` и показать в панели строку `[AlexTerminal] каталог недоступен, открыт ~`.
3. Вывести сохранённый scrollback, затем разделитель `── восстановлено 18.10.2026 10:00 ──` (цвет `fg_muted`), затем запустить shell.
4. Удалённые панели: по настройке `reconnect_remote`:
   - `ask` (по умолчанию) — в панели плашка «Переподключиться к srv-01?» `[Enter] Да  [Esc] Нет`.
   - `auto` — команда выполняется сразу.
   - `never` — обычный shell.
5. Если слепок повреждён — попробовать `.bak`; если и он не читается — чистый запуск и уведомление с путём к файлу.
6. Запуск с флагом `--no-restore` — чистое окно, слепок не затирается до первого сохранения.
7. Запуск с `--restore-from <file>` — для отладки.

**Автосохранение слепка** сервером: при структурном изменении (дебаунс 1 с), каждые `autosave_interval_sec`, при выходе.

### 4.9 Открыть папку в Finder / файловом менеджере

- Действие «Открыть папку» (`Cmd+Shift+O`, контекстное меню вкладки и панели, меню `File`).
- Путь — cwd foreground-процесса активной панели (OSC 7, иначе `procinfo`). Для удалённой панели действие недоступно (серое) с подсказкой «удалённая сессия».
- macOS: `open <dir>` (открыть папку) и `open -R <dir>` (показать в родительской). Linux: `xdg-open <dir>`; если `xdg-open` нет — `gio open`.
- Также: «Открыть в редакторе» (`Cmd+Shift+I`) — команда из настройки `editor_command` (`code {path}` по умолчанию), и «Копировать путь» (`Cmd+Alt+C`).
- Перетаскивание файла из Finder в панель вставляет экранированный путь.

### 4.13 Профили

Профиль — шаблон вкладки. Хранится в конфиге (`[[profiles]]`), редактируется в окне настроек на вкладке «Профили».

```toml
[[profiles]]
name = "default"               # обязательный профиль; используется для Cmd+T
shell = ""                     # пусто = $SHELL
args = []
cwd = "inherit"                # inherit | home | "/path"
command = ""                   # выполняется после запуска shell (вводится как строка + Enter)
env = { }
color = ""                     # пусто = без метки; иначе hex или имя токена темы (accent_remote …)
icon = ""                      # имя глифа Nerd Font, показывается вместо индикатора Idle
title = ""                     # пусто = автозаголовок
remote = false                 # считать вкладку удалённой сразу (для ssh-профилей индикатор Remote без ожидания эвристик)

[[profiles]]
name = "prod"
command = "ssh prod-01"
color = "#D97A7A"
icon = "nf-md-server"
remote = true
title = "prod-01"

[[profiles]]
name = "api"
cwd = "/Users/a/src/api"
command = "git status"
color = "#7FB3C8"
```

- Создание: `Cmd+Alt+T` → список профилей с поиском; `File → New Tab from Profile`; CLI `--profile`; долгое нажатие на `[+]` в сайдбаре.
- Профиль запоминается во вкладке (`profile` в слепке), чтобы «Перезапустить shell» (`Cmd+Shift+R`) и «Дублировать вкладку» воспроизводили его.
- Команда из `command` отправляется в PTY после первого `OSC 133;A` (готов промпт), либо через 500 мс, если интеграции нет; сама команда попадает в историю панели.
- При переподключении удалённой панели (§4.8) используется `command` профиля, если он есть, иначе — последняя удалённая команда из истории.
- Удаление профиля не трогает существующие вкладки; они продолжают ссылаться на `default`.

### 4.14 Локализация

- Два языка интерфейса: английский и русский. Все строки UI, меню, диалогов, окна настроек и сообщений об ошибках — в `locales/<lang>/*.ftl` (Fluent). Хардкод строк в коде запрещён (lint-тест: грепом по `at-ui` на русские/английские фразы вне `locales/`).
- Выбор языка: `ui_language = "system" | "en" | "ru"`. При `system` берётся первый язык из системных предпочтений; если он не `ru`, используется `en`.
- Переключение языка применяется без перезапуска.
- Названия горячих клавиш в палитре команд локализуются; сами сочетания — нет.
- Строки из терминала (вывод программ) не переводятся и не трогаются.
- Форматы дат и чисел (разделитель `── восстановлено … ──`, tooltips) — по выбранной локали.

## 6. Шрифты и цвета

### 6.1 Принципы (меньше усталости глаз)

1. Не использовать чистый чёрный и чистый белый: тёмная тема — холодно-серый с лёгким синим подтоном, светлая — тёплая «бумага».
2. Контраст основного текста к фону 8–10:1 по WCAG (достаточно для чёткости, но без «вибрации»). Приглушённый текст — 4.5:1.
3. Умеренная насыщенность ANSI-цветов: все 16 цветов читаются на фоне (≥ 4.5:1 для обычных, ≥ 3:1 для ярких на тёмном фоне), без неоновых оттенков.
4. Акцентные цвета индикаторов отличаются и по тону, и по яркости (доступно при дейтеранопии).
5. Межстрочный интервал 1.3, кегль 13–14 pt, без мигания курсора по умолчанию, без полного мерцания при звонке (только плавная вспышка рамки 150 мс).
6. Тонкий (1 px) разделитель панелей цветом `border`, без ярких рамок.

## 8. Нефункциональные требования

| Метрика | Требование |

| Задержка ввода (нажатие → кадр) | ≤ 10 мс на 120 Гц, ≤ 16 мс на 60 Гц |

## 10. Тестирование

- Unit: операции над деревом вкладок (создание, закрытие с promote, перемещение, вложение с ограничением глубины), раскладки и минимальные размеры, round-trip слепка, парсер OSC 7770/133/7, ротация истории, keymap (разбор строк «cmd+shift+t», конфликты).
- Интеграция: headless `at-term` с реальным PTY — запуск `zsh`/`bash`/`fish`, проверка приходящих OSC из shell-интеграции, определение `Running`/`Remote` по сценариям (`sleep 2`, `ssh -o BatchMode=yes localhost` в CI с локальным sshd).
- Демон: тесты протокола через тестовый клиент — создать вкладки, отсоединиться, подключиться снова и сверить состояние; два клиента одновременно; несовпадение версии протокола; `SIGTERM` демону → слепок записан, процессы завершены за ≤ 5 с.
- Локализация: тест полноты — каждый ключ из `en` есть в `ru` и наоборот; тест отсутствия хардкода строк в `at-ui`.
- VT-совместимость: прогон `vttest` и набора esctest вручную перед релизом; snapshot-тесты рендера сетки через `alacritty_terminal`.
- Восстановление: тест «убить процесс `SIGKILL` в случайный момент → запуск → состояние соответствует последнему слепку или `.bak`».
- Ручной чек-лист (в `docs/qa.md`): горячие клавиши на обеих платформах, Finder/xdg-open, drag-and-drop, тёмная/светлая тема, HiDPI и смена монитора, Wayland и X11.
- CI: GitHub Actions — `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test` на `macos-14` и `ubuntu-22.04`; сборка артефактов на тег.

## 13. Принятые допущения

1. GUI-фреймворк — `iced`; окончательно фиксируется по итогам M0.
2. Вложенные вкладки создаются только явным действием пользователя (не автоматически при ssh).
3. При 2–3 панелях доступен только вертикальный стек; сетка 2×2 — только при 4.
4. «История команд на окно» трактуется как: (а) собственный лог команд панели в файле и (б) отдельный `HISTFILE` для shell панели. Scrollback тоже сохраняется, но это отдельная настройка.
5. На Linux основной стандарт сочетаний — `Ctrl+Shift+<буква>`.
6. Сессии живут, пока запущено приложение; после выхода и перезагрузки работает слепок. Сетевой доступ к серверу сессий не планируется.
7. Один экземпляр приложения на пользователя; повторный запуск передаёт запрос уже открытому.
